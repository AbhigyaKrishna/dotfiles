# systemd system units this configuration needs enabled.
#
# NOT a full inventory of what is enabled on this machine — roughly thirty
# units are, and the rest (sddm, NetworkManager, docker, ufw, bluetooth, cups,
# tailscaled, limine-snapper-sync ...) are deliberately left out. They are
# either distro defaults or per-machine choices, not things this repo
# configures. Only the units something tracked here depends on belong in this
# file.
#
# Re-enable on a fresh machine:
#   grep -v '^#' meta/systemd-system-units.txt | xargs -r sudo systemctl enable --now
#
# Note this file is for SYSTEM units and needs sudo. The user units are in
# meta/systemd-user-units.txt and must not be enabled with it.

# TLP is the power manager (see meta/system/tlp.d/10-local.conf). Without
# tlp.service the settings in that drop-in are never applied at boot.
tlp.service

# tlp-pd exposes TLP through the power-profiles-daemon D-Bus interfaces, which
# is what noctalia's PowerProfile bar widget talks to. Without it the widget
# has nothing to read and the profile switching UI goes dead.
tlp-pd.service

# Kills a runaway app before the machine locks up. The thresholds live in the
# app.slice drop-in under common/systemd and in meta/system/oomd.conf.d; this
# is the daemon that acts on them. Without it both are inert.
systemd-oomd.service

# Trims the pacman cache, which otherwise grows without bound. Needs
# pacman-contrib.
paccache.timer

# Monthly integrity check of the btrfs root. The unit is templated on the
# mountpoint, and "-" is the escaped form of "/":
#   sudo systemctl enable --now btrfs-scrub@-.timer
btrfs-scrub@-.timer

# Hourly snapshots of the root subvolume. snap-pac already snapshots around
# pacman transactions; this adds the timeline between them, and
# limine-snapper-sync makes both bootable from the menu. The same timer also
# drives the /home timeline once the 'home' config exists (meta/system/
# snapper-home creates it); no separate timer is needed.
snapper-timeline.timer

# SMART disk monitoring. Watches every drive DEVICESCAN finds, runs periodic
# self-tests, and alerts through meta/system/smartd-notify (journald + a
# critical desktop notification) since there is no MTA for email. The config
# and its handler have to be installed first — see meta/system/smartd.conf.
smartd.service

# Keeps the LVFS metadata current so `fwupdmgr get-updates` stays meaningful.
# Refreshes metadata only — it never installs firmware. Note LVFS carries
# nothing for this laptop's BIOS (HP does not publish the Pavilion Gaming
# 15-ec2xxx there), so this is mostly about being covered if that changes or a
# component vendor starts publishing.
fwupd-refresh.timer

# Locks the graphical session Before=sleep.target, so a suspend that does not
# go through niri-power-action (the noctalia session-menu button, a hand-typed
# `systemctl suspend`) can never sleep an unlocked session. See the unit and
# its helper in meta/system/ — both have to be installed first (they are not
# stowed and the helper lives in /usr/local/bin), then this enabled.
lock-before-sleep.service

# Drives the CPU and GPU fans from the EC directly, because the stock curve on
# this chassis never ramps and hp-wmi's control of it is inert (see the fan
# control note in meta/packages.txt for the measurements). Install the matching
# config first, then enable:
#   sudo nbfc config -s "HP Pavilion Gaming Laptop 15-ec2xxx"
# Check it with `nbfc status -a`. Note it reports fan speed as a PERCENTAGE of
# the configured range, not RPM — nothing on this machine reports true RPM, since
# hp-wmi's fan inputs are the broken ones. The percentage is still the useful
# signal: watching it step 100 -> 60 as the machine cools is how you confirm the
# curve is actually being driven rather than sitting at a fixed value.
nbfc_service.service

# Caps the 5600H's junction temperature and sustained power budget as a second
# line of defence behind the fans, so the part stabilises below Tjmax instead of
# bouncing off it. Needs ryzenadj from the AUR, plus the unit and its helper
# installed from meta/system/. The caps are volatile SMU writes, so the unit is
# also WantedBy the sleep targets and re-applies on every resume; enabling it
# here covers only the boot path.
#
# ORDER MATTERS: enable this only AFTER nbfc_service is working, and set the cap
# from measurements taken with the fans behaving. It is currently 90°C, which
# suits an idle in the low 60s. The earlier value of 85°C was chosen while the
# fans were still stuck and the machine idled at 74.8°C — on a machine in that
# state a cap that close to idle throttles the part at rest, trading a heat
# problem for a permanent performance one.
ryzenadj-thermal.service
